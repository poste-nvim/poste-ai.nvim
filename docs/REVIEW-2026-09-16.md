## Bugs fixed

1. **Intraword underscores italicized and concealed** (`chat/render.lua`)
   — the italic scan accepted any `_x_y_` span, but CommonMark disables
   `_` emphasis inside words. Snake_case identifiers in plain prose
   (`my_table_name`) got the middle segment highlighted as italic AND
   both underscores concealed — the rendered text showed
   `mytablename`, visibly corrupted. Word-boundary check per
   CommonMark (`my_table_name` stays literal; `this is _real_` still
   italicizes; intraword `*bold*` keeps working). Tests: intraword
   negative + word-boundary positive.

2. **`text.truncate` exceeded its own width contract for `limit <= 3`**
   (`text.lua`) — it appended a full `"..."` to `limit - 3` (often 0)
   characters, e.g. width 3 for a 1-column budget. Callers guard this
   today (`math.max(1|4, …)`), but the outline drawer passes
   `width - 2 - ts_w` and any future narrow call would overflow the
   drawer/timestamp padding. Now only the dots that fit are returned;
   `limit <= 0` → `""`. Tests: width ≤ limit for limits 0–3.

3. **`data:` payload trimming was inconsistent between the two colon
   forms** (`provider/sse.lua`) — `data:x` trimmed surrounding
   whitespace, `data: x` did not, so a proxy emitting a double space
   (`data:  {…}`) handed the decoder `" {…}"`; `vim.json.decode`
   rejects leading whitespace, the delta silently dropped. Both forms
   now trim leniently. Test: double-space classify.

## Added

**`:'<,'>PosteAIChat` on a visual selection** (`commands.lua`) —
`mention.range_mention()` existed and was tested, but nothing in the UI
could reach it: the visual-select flow had no generic-chat entry point.
`PosteAIChat` now accepts a range: on a selection it opens the chat and
prefills the input with `@path(l1-l2)` (appending to an existing draft
instead of replacing it); unnamed buffers warn instead of half-opening
the chat. `context_id` argument composes (`:'<,'>PosteAIChat db`).
Documented on the docs site (poste-ai/chat). Tests: prefill, draft
append, unnamed-buffer warn.

## Recorded, not changed (with rationale)

- **`/unknown args…` (with a space) is sent to the LLM as chat text**
  while bare `/unknown` warns "unknown command" (`chat/slash.lua`
  `submit`) — reads deliberate ("maybe the user wanted to ask about
  /topic"), but a typo'd slash command with arguments silently becomes
  a chat message. Flag for a future decision, not changed.
- **A failed-before-first-delta stream leaves a label-only assistant
  block** (`✦ model` with empty content) above the error block in the
  view and the session (`chat/stream.lua` `compose` failure path).
  Cosmetic; `history_messages` skips empty content so the LLM never
  sees it. Removing the placeholder would need a conversation
  `remove_last` API — not worth it for the label.
- **`mention.complete` is a silent no-op when zero candidates match**
  (no "no matches" feedback) (`chat/mention.lua`). Minor UX.
- **The slash palette only retargets from `TextChangedI`** — normal-mode
  buffer edits (`p` in the input) don't re-filter an open palette
  (`chat/window.lua` `setup_autocmds`). Narrow window of confusion.
- **`enforce_input_height` fights a deliberately dragged-taller input
  pane** on every WinResized (`chat/window.lua`). Design decision
  (input is a fixed 5-line strip), recorded so the fight is known.
- **Strict-SSE multi-line `data:` events** (one event spanning several
  `data:` lines, joined with `\n` per spec) are dispatched as separate
  events. Fine for every OpenAI-compatible provider; would matter for
  a strict-SSE adapter.
